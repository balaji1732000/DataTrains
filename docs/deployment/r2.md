# Cloudflare R2 artifact storage

DataTrains uses one private R2 bucket for raw captures, temporary multipart
objects, derived validation data, and release exports. Public bucket access must
remain disabled. Only the Go API and worker receive the S3-compatible R2
credentials.

## Object layout

```text
staging/multipart/<random-id>             untrusted in-progress upload
raw/sessions/<session-id>/<artifact>      verified immutable capture
derived/sessions/<session-id>/...         worker output
releases/<release-id>/...                 deterministic release
bundles/<release-id>.zip                  deterministic streaming ZIP export
```

Raw screen recordings never move directly into a release. The optional
redacted-video path is described in [`video-redaction.md`](video-redaction.md).

The Collector never chooses a storage key. It supplies a clean artifact path to
the Go API, which derives the session-scoped raw key and a random staging key.

## Resumable upload protocol

1. The Collector starts or resumes an upload with
   `POST /v1/sessions/{session_id}/multipart-uploads` and declares the path,
   media type, byte size, and full SHA-256.
2. The API persists the R2 upload ID and a seven-day upload record in PostgreSQL
   and returns a 16 MiB part plan plus already completed parts.
3. For each missing part, the Collector requests a short-lived, part-specific
   presigned URL, streams that exact byte range directly to R2, and sends the
   returned quoted `ETag` to the API.
4. The API persists each part, so closing or restarting the Collector does not
   lose upload progress.
5. Completion assembles the temporary object. The API reads it back, verifies
   its byte count and full SHA-256, copies it to a create-only `raw/` key, then
   registers the artifact in PostgreSQL. Unverified bytes never become raw data.

R2 requires every non-final part to be at least 5 MiB and permits at most 10,000
parts. DataTrains uses 16 MiB parts and limits one artifact to 20 GiB. R2 also
aborts incomplete multipart uploads after seven days by default; keep that rule
enabled. The API-level upload record expires on the same schedule.

## Bucket policy checklist

- Create a private Standard-class bucket in the selected jurisdiction.
- Create a dedicated S3 API token limited to this bucket with object read/write
  permission. Do not use an account-wide token.
- Store the access key and secret only in Google Secret Manager.
- Keep the default seven-day incomplete-multipart cleanup, or configure an
  explicit equivalent lifecycle rule.
- Add lifecycle cleanup for staging objects that survive an interrupted
  verification or promotion. A seven-day expiration for `staging/multipart/` is
  suitable for V1.
- Do not add R2 lifecycle deletion to `raw/`, `derived/`, or `releases/`.
  Lifecycle deletion bypasses application legal holds. Govern those prefixes
  through the audited API/worker flow described in
  [Retention, legal hold, and erasure](data-governance.md).
- Enable Cloudflare account audit logs appropriate to the chosen plan and retain
  deployment evidence outside the bucket.

## CORS

The Tauri Collector uploads through its native HTTP client, so browser CORS does
not authorize or protect it. If a browser-based uploader is enabled, copy
`infra/cloudflare/r2-cors.example.json`, replace `https://app.example.com` with
the exact production origin, and add the policy under the bucket's Settings →
CORS Policy. Never use `*` for a credentialed production origin.

`ETag` must be exposed because multipart completion needs the ETag returned for
each uploaded part. Origins must not include a path or trailing slash. Validate
the rule with one real presigned upload after provisioning; policy propagation
can take several seconds.

## Required Cloud Run secrets

```text
TRAJECTORY_R2_ENDPOINT=https://<account-id>.r2.cloudflarestorage.com
TRAJECTORY_R2_BUCKET=<private-bucket-name>
TRAJECTORY_R2_ACCESS_KEY_ID=<Secret Manager reference>
TRAJECTORY_R2_SECRET_ACCESS_KEY=<Secret Manager reference>
```

Provisioning the bucket or access token is an external account change and must
be performed only after the owner approves the exact name, jurisdiction,
retention policy, and credential scope.
